DOCUMENTACION TECNICA - JOVI AR APP
=====================================
Version: 1.0
Fecha:   17/12/2025
Proyecto: Aplicacion Movil de Realidad Aumentada y Exploracion Urbana

1. INTRODUCCION Y OBJETIVOS
---------------------------
Jovi AR es una aplicacion movil multiplataforma (Android/iOS) disñada para fomentar 
el descubrimiento del patrimonio local y la interaccion social entre estudiantes 
mediante gamificacion. La aplicacion permite a los usuarios explorar mapas, 
descubrir puntos de interes mediante Realidad Aumentada (RA simulada/futura), 
participar en concursos de fotografia y seguir la actividad de sus companeros.

Objetivos Tecnicos:
- Desarrollar una aplicacion fluida y reactiva utilizando Flutter.
- Implementar un sistema de backend serverless escalable mediante Firebase.
- Integrar mapas vectoriales de alto rendimiento con Mapbox.
- Crear un flujo de moderacion de contenido (aprobacion de sitios subidos por usuarios).


2. ARQUITECTURA DEL SISTEMA
---------------------------
El proyecto sigue una arquitectura Modular basada en Servicios, separando claramente 
la Capa de Presentacion (UI) de la Logica de Negocio y Datos.

2.1 Diagrama de Capas (Logico)

A. Capa de Presentacion (Screens & Widgets)
   - Maneja la UI y la interaccion con el usuario.
   - Es "reactiva": se redibuja basandose en Streams de datos.
   - Ubicacion: lib/screens/, lib/widgets/

B. Capa de Servicios (Logic/Services)
   - Actua como intermediario entre la UI y el Backend.
   - Contiene toda la logica de negocio "pesada".
   - Ubicacion: lib/services/
     * auth_service.dart: Gestion de sesion (Login, Registro, Logout).
     * api_service.dart: CRUD de entidades (Sitios, Votos, Usuarios).
     * settings_service.dart: Persistencia local.

C. Capa de Datos (Backend - Firebase)
   - Firestore: Base de datos principal.
   - Storage: Almacenamiento de blobs (imagenes).
   - Authentication: Gestion de identidades.


3. MODELO DE DATOS (FIRESTORE SCHEMA)
-------------------------------------

3.1 Coleccion 'users'
   Almacena el perfil publico y social del usuario.
   - ID: uid (Firebase Auth)
   - nickname (String): Nombre unico.
   - email (String)
   - followers (Array<String>): IDs de quien le sigue.
   - following (Array<String>): IDs de a quien sigue.

3.2 Coleccion 'sitios'
   Lugares subidos por los usuarios para aprobacion.
   - title, description (String)
   - authorId (String): UID del creador.
   - lat, lng (Number): Coordenadas.
   - imageUrl (String): URL en Storage.
   - status (String): 'pending_review', 'approved', 'denied'.
   - appealCount (Number): Contador de apelaciones.

3.3 Coleccion 'contest_entries' (Concurso)
   Participaciones para el concurso de fotografia.
   - authorId, lat, lng, imageUrl
   - likes (Number): Contador de votos.
   - likedBy (Array<String>): IDs de usuarios que votaron.
   - school, classId (String): Filtros escolares.

3.4 Coleccion 'usernames'
   Indice para garantizar unicidad de nicks.
   - ID: nickname (en minusculas)
   - userId: UID del propietario.

6. FLUJOS CRITICOS
------------------

6.1 Registro con Nickname Unico
   Se usa una Transaccion en Firestore:
   1. Lee 'usernames/{nickname}'.
   2. Si no existe, crea usuario y reserva nick.
   3. Si existe, aborta.

6.2 Sistema de Votacion (Concurso)
   Operacion atomica (Transaccion):
   1. Lee documento de entrada.
   2. Verifica si usuario ya esta en 'likedBy'.
   3. Si esta -> quita ID y decrementa likes.
   4. Si no esta -> añade ID e incrementa likes.
